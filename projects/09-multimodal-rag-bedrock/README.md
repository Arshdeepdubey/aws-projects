# 09 — Building a Multimodal RAG Using Foundation Models and AWS

Retrieval-augmented generation over documents that contain **both text and images**: PDFs, scanned
pages, diagrams, screenshots. Text and images land in the same vector space via Amazon Titan
Multimodal Embeddings, so "show me the diagram of the payment flow" retrieves the picture, and the
answer is generated by Claude on Amazon Bedrock with citations back to the source page.

```
S3 documents/ ──(ObjectCreated)──> Ingestion Lambda
                                      ├─ PDF   ──> Textract (async) ──> text blocks ──┐
                                      ├─ image ──> Claude vision caption ─────────────┤
                                      └─ text  ──────────────────────────────────────┤
                                                                                      ▼
                                                          Titan embeddings (text + multimodal)
                                                                                      │
                                                            OpenSearch Serverless (k-NN vector index)
                                                                                      │
HTTP API  POST /ask ──> Query Lambda ──> hybrid retrieve (vector + keyword) ──> Claude (Bedrock) ──> answer + citations
```

## Design decisions worth knowing

**One index, two modalities.** Titan Multimodal Embeddings (`amazon.titan-embed-image-v1`) maps
images and short text into the same 1024-dim space, so a single k-NN query returns both. Long text
chunks use `amazon.titan-embed-text-v2:0` (1024-dim as well) in a separate field — mixing a
1024-dim text-only vector with a multimodal one in the same field would silently ruin recall.
Each document carries `modality` so the retriever can weight or filter.

**Hybrid retrieval, not pure vector.** Vector search alone misses exact identifiers (invoice
numbers, error codes, part numbers). The query Lambda runs a k-NN query and a BM25 query and fuses
them with reciprocal rank fusion — about 20 lines, consistently better than either alone.

**No opensearch-py dependency.** `src/shared/aoss.py` signs requests with SigV4 using botocore
(already in the Lambda runtime) and calls the collection endpoint over HTTPS. That keeps the
deployment package tiny and avoids a Docker bundling step for CDK.

**Images are captioned as well as embedded.** A picture retrieved by vector similarity is useless
to a text LLM unless something describes it. Ingestion asks Claude for a dense caption, stores it
alongside the image embedding, and the query path passes the actual image bytes back to Claude when
the answer depends on it.

## Layout

```
infra/                CDK: buckets, OpenSearch Serverless collection + policies, Lambdas, HTTP API
src/shared/aoss.py    SigV4-signed OpenSearch Serverless client (no third-party deps)
src/shared/bedrock.py Embedding and generation helpers with retry/backoff
src/ingestion/        S3 + Textract-completion handler, chunking, indexing
src/query/            Retrieval, reciprocal rank fusion, prompt assembly, citation extraction
scripts/              create_index.py, ingest_local.py, ask.py
notebooks/            01-evaluate-retrieval.ipynb — recall@k and answer grading
```

## Prerequisites

- AWS CDK v2, Python 3.11+
- **Bedrock model access enabled** in the region for: `amazon.titan-embed-text-v2:0`,
  `amazon.titan-embed-image-v1`, and a Claude model. Enable them in the Bedrock console under
  *Model access* — deployment succeeds without it but every invocation returns `AccessDeniedException`.
- Default region is `us-east-1` because model availability is widest there. Change
  `bedrock_region` in `cdk.json` if your models are elsewhere.

## Deploy

```bash
cd infra
pip install -r requirements.txt
cdk bootstrap
cdk deploy MultimodalRagStack

export DOCS_BUCKET=$(aws cloudformation describe-stacks --stack-name MultimodalRagStack \
  --query "Stacks[0].Outputs[?OutputKey=='DocumentsBucket'].OutputValue" --output text)
export AOSS_ENDPOINT=$(aws cloudformation describe-stacks --stack-name MultimodalRagStack \
  --query "Stacks[0].Outputs[?OutputKey=='CollectionEndpoint'].OutputValue" --output text)

python ../scripts/create_index.py --endpoint "$AOSS_ENDPOINT" --index multimodal-rag
aws s3 cp report.pdf "s3://$DOCS_BUCKET/documents/report.pdf"
```

## Ask

```bash
curl -s -X POST "$API_URL/ask" -H 'content-type: application/json' -d '{
  "question": "What did the architecture diagram say about failover between regions?",
  "topK": 6
}' | jq
```

Response shape:

```json
{
  "answer": "The diagram shows active-passive failover ...",
  "citations": [
    {"documentId": "report.pdf", "page": 12, "modality": "image", "score": 0.81,
     "s3Uri": "s3://.../pages/report-p12.png"}
  ],
  "usage": {"inputTokens": 4210, "outputTokens": 260}
}
```

## Evaluating it

A RAG system that is not measured is a demo. `notebooks/01-evaluate-retrieval.ipynb` builds a small
question set from your own documents and reports:

- **recall@k** — is the right chunk retrieved at all (fix retrieval before prompts)
- **answer faithfulness** — an LLM judge checks every claim against the retrieved context
- **citation accuracy** — do cited pages actually contain the claim

## Cost

OpenSearch Serverless has a floor: 2 OCUs minimum (1 indexing + 1 search) ≈ **$0.24/hour ≈ $175/month**
even when idle. This is the single biggest cost in the template. For dev, set
`use_serverless_collection=false` in `cdk.json` to fall back to an S3 Vectors / in-Lambda FAISS path,
or destroy the stack between sessions. Bedrock is per-token: Titan embeddings ~$0.0001/1k tokens,
Claude generation the usual per-token rate.

cd infra && cdk destroy MultimodalRagStack
